# Skill: data-audit

## Purpose
「データが揃っているという前提で分析を始めて、あとで欠損が判明する」を防ぐ。
分析開始前にデータ品質を確認し、精度への影響を明示する。

## Trigger
- 「データを受け取ったので確認して」
- 「このCSVで分析できるか確認して」
- 新規顧客のデータ受領時
- 毎月のデータ更新時

## Required Inputs
- データファイルのリスト（CSVパス・ファイル名）
- 対象期間（年月）

## Optional Inputs
- client.json（どのデータが必要かの参照）
- 前回のdata-audit-report.md

## Validation
- ファイルが実際に存在するか
- ヘッダー行が存在するか
- データ行が0件でないか

## Analysis Steps
1. 各ファイルを開いてヘッダーと行数を確認
2. 必須カラムの存在を確認（Metric Dictionaryと照合）
3. 欠損値・異常値（負値・極端な外れ値）をチェック
4. 期間カバレッジを確認（必要期間のデータが揃っているか）
5. データ粒度を確認（日次/週次/月次、SKU別/店舗別等）
6. 分析可能レベルを判定

## Decision Rules
### 分析可能レベル判定

| レベル | 条件 | 対応 |
|--------|------|------|
| A：フル分析可能 | 必須データが全て揃い欠損5%以下 | 全Skill実行可能 |
| B：主要分析可能 | 必須データの80%以上あり | 一部Skillのみ実行可能 |
| C：限定分析 | 必須データの50〜80% | 売上・CVR分解のみ可能 |
| D：分析困難 | 必須データの50%未満 | 追加データ提供を依頼 |

## Output Contract
### 必須出力（data-audit-report.md）

```markdown
# データ監査レポート

## 判定：{A/B/C/D} — {判定理由}

## データ一覧
| ファイル | 期間 | 行数 | 欠損率 | 状態 |
|---------|------|------|--------|------|

## 利用可能な分析
- ✅ kpi-diagnosis
- ✅ sku-analysis
- ❌ ad-analysis（広告データなし）

## 不足データ・依頼事項
1. {不足データ1}：{入手方法}
2. {不足データ2}：{入手方法}

## データ品質上の注意点
{異常値・欠損・粒度の違いなど}
```

## Missing Data Behavior
- ファイルが存在しない場合 → 「未提供」として記録し追加依頼リストへ追加
- 必須カラムが欠損 → 代替計算方法があれば提示

## Human Review
- 「不足データ・依頼事項」を顧客に送付する前に文面を確認
- データ品質上の注意点が分析結果に影響する場合は明示

## Test
### 正常系
- 全データ揃っている → レベルA判定
- 広告CSVのみない → レベルB判定、ad-analysisを「❌」に

### 異常系
- 空ファイル → 「データが空です。正しいファイルを再送してください」
- 文字化け → 「エンコーディングエラー。UTF-8またはShift-JISで保存して再送してください」
