# 出力フォーマット — 標準レポート構成

## レポート出力の原則

1. **数字は解釈と一緒に提示する**: 数字だけの羅列は禁止
2. **事実と仮説を明確に分ける**: [事実]タグと[仮説]タグを使い分ける
3. **全改善機会は円で示す**: 「改善余地あり」ではなく「月次¥XXX,XXX の機会」
4. **施策は具体的に**: 「SEOを改善する」ではなく「商品名に『○○』というキーワードを追加する」
5. **不足データは隠さない**: 分析の限界と必要なデータを明示する

## FIHEAVテンプレート（発見事項の記述形式）

重要な発見事項を記述する際は以下の構造を使用する:

```
### [発見事項タイトル]

**Fact（事実）**: データから直接確認できる事実
  例: 「商品BのCVRは0.8%。店舗平均2.2%の36%水準。前月比でも-0.3pt低下している。」

**Interpretation（解釈）**: 事実が示す状況の解釈
  例: 「集客はできているが（月次2,800UU）、購入に至っていない。アクセス効率が著しく低い。」

**Hypothesis（仮説）**: 考えられる原因（複数挙げる）
  例:
  - 仮説A（最有力）: 競合比で価格が20%高い（競合¥2,980 vs 自社¥3,580）
  - 仮説B: 商品画像が3枚と少なく、情報量が不足している
  - 仮説C: 流入KWと商品の検索意図がミスマッチ

**Evidence（証拠）**: 仮説を支持するデータ
  例: 「競合A社の同カテゴリ商品が¥2,980で販売中（手動確認）。自社は¥3,580。」

**Missing Evidence（不足している証拠）**:
  例: 「流入KW別CVRのデータがあれば、仮説Cの検証ができる。」

**Action（実行施策）**: 具体的な改善アクション
  例:
  1. 商品画像を高解像度+シーン画像で8枚以上に増やす（1週間以内）
  2. 価格を¥3,280に引き下げて競合と差を縮める（利益シミュレーション確認後）

**Expected Impact（期待効果）**:
  例: 「CVRが1.5%に改善した場合: 2,800UU × (1.5% - 0.8%) × ¥3,280 = ¥64,288/月の売上増」

**Validation（検証方法）**:
  例: 「施策実施2週間後のCVRを比較。目標: CVR 1.2%以上。ガードレール: 客単価 ¥3,000以上維持。」
```

## 禁止パターン（出力の質を保つためのルール）

以下の表現・形式は使用しない:

| 禁止パターン | 理由 | 代替表現 |
|------------|------|---------|
| 数字の羅列のみ | 解釈なしでは判断できない | 数字 + 解釈 + 施策をセットで |
| 「相関がある」→「原因だ」 | 因果推論の誤り | 「相関がある。因果を確認するには○○が必要」 |
| 「ROASが低いから広告を削減する」 | LTVを無視している | ROAS + LTV + 新規獲得コストで総合評価 |
| 「売上が高い商品は良い商品」 | 粗利・LTVを無視している | 売上・粗利・新規獲得・LTV貢献で評価 |
| 「欠品中の売上低下は需要低下」 | 欠品期間の需要データは無効 | 「欠品期間は需要データとして使用不可。通常期のデータで評価する」 |
| 「イベント日と通常日を同列比較」 | イベント効果を分離しないと誤判断 | 必ずイベントフラグを付与して分離分析 |
| 「SEOを改善する」 | 曖昧すぎる施策 | 「商品名に『○○』というキーワードを追加する」 |
| 「CVRが悪い」だけで終わる | 原因と施策がない | CVR低下の原因仮説と具体的対処を必ず追記 |
