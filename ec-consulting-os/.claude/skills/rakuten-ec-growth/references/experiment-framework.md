# 検証フレームワーク — 施策の効果測定と因果推論

## 基本原則

### 相関と因果の区別
- **相関**: AとBが同時に変化した（観察事実）
- **因果**: AがBを引き起こした（検証が必要）
- EC分析では因果を証明することは難しいが、代替説明を排除することで仮説の確信度を高める

**禁止表現**:
- 「RPPを増やしたので売上が増えた」→「RPP増加と売上増加が同時期に観察された。他の要因（イベント・季節・競合変化）を確認する」
- 「CVRが下がったのはレビューのせいだ」→「CVR低下とレビュー件数の相関がある。他の要因（価格変更・競合・在庫SKU欠品）も確認する必要がある」

## Before/After 比較の設計

### 基本設計
```
測定期間の設定:
  Pre期間（介入前）: 施策実施前の同期間
  Post期間（介入後）: 施策実施後の観測期間

推奨設計:
  Pre期間 = Post期間（同じ日数・同じ曜日構成）
  最低観測期間: 施策タイプにより異なる（下表参照）
```

### 施策タイプ別最低観測期間

| 施策タイプ | 最低観測期間 | 理由 |
|-----------|------------|------|
| RPP入札単価変更 | 2週間 | データ蓄積・最適化に時間が必要 |
| 商品画像差し替え | 2週間 | CVRの安定化まで時間がかかる |
| 価格変更 | 2〜3週間 | 短期的な反応と落ち着きを両方確認 |
| 商品名・SEO変更 | 4〜8週間 | 楽天検索への反映に時間がかかる |
| F2転換施策（メール） | 90日間 | F2転換率は90日で計測 |
| LTV施策 | 180〜365日 | LTVの変化は長期で測定 |
| クーポン施策 | 4週間 | 配布から利用までのタイムラグ |
| 在庫補充後の効果 | 2週間 | 在庫回復後のCVR・売上の安定化 |

## 対照群の設定オプション

楽天ECでは完全なランダム化比較試験（RCT）は難しい。以下の代替手段を活用する。

### オプション1: 非対象商品を対照群にする
- **設計**: 施策対象商品（介入群）vs 施策非対象の類似商品（対照群）
- **適用場面**: 商品画像改善・価格変更・RPP変更
- **注意**: 対象商品と非対象商品が類似条件であることを確認する

### オプション2: イベント前後の通常期を対照群にする
- **設計**: イベント期の実績 vs 直前直後の通常期を平均した期待値
- **適用場面**: イベント施策の効果測定
- **計算**: イベント増分 = 実績 - (イベント前2週間平均 + イベント後2週間平均) / 2 × イベント日数

### オプション3: 時系列比較（前年同月比）
- **設計**: 今期 vs 前年同期
- **適用場面**: 季節性を含む中長期の施策評価
- **注意**: 市場環境・競合状況の変化を考慮する

### オプション4: セグメント分割テスト（楽天RMS機能活用）
- **設計**: クーポンの配布対象者 vs 非配布者での効果比較
- **適用場面**: クーポン・R-Mail施策
- **注意**: セルフセレクションバイアス（クーポン取得者はもともと購入意向が高い可能性）に注意

## 交絡因子チェックリスト

Before/After比較の際に必ず確認すべき外部要因:

| 交絡因子 | 確認方法 | 対処法 |
|---------|---------|--------|
| 季節性 | 前年同月のデータと比較 | 前年同月比を補正値として使用 |
| 楽天イベント | イベントカレンダーと照合 | 通常期のみで比較、イベント効果は別途測定 |
| 競合変化 | 競合の価格・施策を定期確認 | 競合調査を記録に残す |
| 価格変更 | 分析期間内の価格変更履歴を確認 | 価格変更前後を別期間として分析 |
| 在庫変動 | 欠品日の確認 | 欠品期間のデータを除外または補正 |
| 天候・外部イベント | 気象データ・ニュース | 特定日の異常値をアウトライヤーとして処理 |
| 楽天アルゴリズム変更 | 同時期の他商品の動向 | 複数商品の同時変動 → 外部要因の可能性 |
| 広告設定変更 | RPP・入札単価の変更履歴 | 施策以外の変更がないことを確認 |

## 8つの標準検証シナリオ

### シナリオ1: 売上減少 ← アクセス低下

**観測**: 売上が前月比-15%
**仮説**: アクセス減少が主因
**検証手順**:
1. アクセス数の前月比を確認 → アクセス-18%, CVR+3%, AOV+0%
2. 寄与度分解 → アクセス要因が売上変動の大部分を説明
3. チャネル別アクセスの内訳 → どのチャネルが減っているか特定
4. RPP予算確認 → 月次予算上限到達で配信停止していないか
5. 楽天検索順位確認 → 主要KWでの順位変動はないか
6. 競合調査 → 競合の広告強化・ランキング変動はないか

**因果への留保**: アクセス低下の原因が特定されるまで、施策は原因候補ごとに優先順位を付けて実施する。

### シナリオ2: アクセス増 + CVR低下 = 売上横ばい

**観測**: アクセス+20%, CVR-15%, 売上ほぼ横ばい
**仮説候補**:
- A: 流入KWの質が低下（無関係なKWからの流入増）
- B: 価格競争力の低下（競合が値下げした）
- C: 商品ページ品質の問題（画像・説明の劣化）
**検証手順**:
1. 流入KW別CVRを確認 → 特定KWのCVRが低い場合は仮説A
2. 競合価格と自社価格を比較 → 価格差が広がった場合は仮説B
3. チャネル別CVRを確認 → RPPのみCVR低下の場合は仮説A（RPP KWの問題）
4. 商品ページ変更の有無を確認 → 変更なければ仮説CよりA/Bを優先

### シナリオ3: 売上増 + 広告費・ポイント増 = 利益減

**観測**: 売上+20%, 営業利益-10%
**仮説**: 販促コストが増加して利益を食っている
**検証手順**:
1. 値引依存度を計算（SALE+クーポン+ポイント）/売上
2. RPP広告費と広告粗利の比較
3. 各費用項目の前月比変化を確認（どのコストが増えたか）
4. 施策別のROIを計算（各施策の増分利益 vs コスト）
**判断**: コスト増加の原因となった施策を特定し、ROIがマイナスのものを停止・見直し

### シナリオ4: 売上低下 ← 主力SKU欠品

**観測**: 売上-30%急落
**仮説**: 欠品による販売停止
**検証手順**:
1. 在庫データで欠品商品・欠品開始日を確認
2. 欠品商品の通常日販 × 欠品日数 = 機会損失を計算
3. 欠品商品以外の売上に変化がないことを確認（欠品以外の要因がないことを確認）
**対処**: P0対応（即時発注・広告停止・入荷日記載）

**重要な誤り**: 欠品中の売上低下を「需要低下」と判断してはいけない。欠品期間の売上データは需要を反映していない。

### シナリオ5: ROAS低 + 高LTV新規獲得商品

**観測**: 特定商品のRPP ROAS 180%（損益分岐ROAS 300%を下回る）
**仮説**: 表面上の赤字だが入口商品として機能している
**検証手順**:
1. 当該商品経由の新規顧客数を確認
2. 新規顧客の90日・180日LTV（粗利）を確認
3. LTVベースのROI計算: (LTV粗利 - CPO) / CPO × 100
4. 他の流入チャネルとの新規顧客LTV比較
**判断**: LTVベースのROIがプラスであれば継続投資。マイナスであれば入口商品としての見直し。

### シナリオ6: SALE売上高 + 通常日弱い

**観測**: マラソン期間の売上が通常日の3倍。通常日はほぼゼロ。
**仮説**: イベント依存構造。通常日の競争力がない。
**検証手順**:
1. イベント依存率を計算
2. 通常日のアクセス・CVRを確認（構造的に低いか）
3. 通常日と比較したイベント日のCVR・客単価の差を確認
4. イベント期獲得顧客と通常期獲得顧客のF2転換率を比較
**施策**: 通常日のRPP・SEO強化。通常日クーポン設計。イベント依存度の段階的低減計画。

### シナリオ7: CVR高 + 検索流入少ない商品

**観測**: 特定商品のCVR 5.8%（店舗平均2.2%の2.6倍）。しかし月次アクセス300UUと少ない。
**仮説**: SEO・集客強化で大きな売上増加が見込める
**機会損失計算**:
1. 目標アクセス数の設定（類似商品の上位25%アクセスを参考）
2. SEO改善機会: 追加アクセス × 現CVR × 客単価
3. RPP投資機会: 投資シミュレーション（入札単価 × 目標クリック数 → 広告粗利）
**施策**: SEO改善（商品名KW追加）+ RPP投資を並行して実施。

### シナリオ8: 新規多 + F2転換率低い店舗

**観測**: 月次新規顧客200人。F2転換率（90日）15%（目標25%）。
**仮説**: 新規獲得施策は機能しているが、リピート定着化が弱い
**検証手順**:
1. 初回購入商品別のF2転換率を比較（入口商品による差があるか）
2. 新規獲得チャネル別のF2転換率を比較（イベント獲得 vs 通常期獲得）
3. 初回購入後のフォローアップ有無を確認
4. 購入商品カテゴリの購入周期を確認（F2転換に時間がかかる商品か）
**F2改善機会**: 200人 × (0.25 - 0.15) × F2客単価 × 粗利率 - 施策コスト

## 成功条件の設定方法

施策ごとに事前に成功条件を定義する。後付けで評価基準を変更しない。

### 成功条件テンプレート
```
【施策名】: ○○商品の商品画像差し替え

主要KPI: CVR
現状値: 1.5%
目標値: 2.0%（+33%）
成功条件: 2週間後のCVRが1.8%以上

ガードレールKPI（悪化を許容しない指標）:
  - 客単価: 現状 ¥4,500 ± 5%以内に収まること
  - 返品率: 現状 2.0% 以下に収まること

観測期間: 2026-XX-XX 〜 2026-XX-XX（2週間）
測定方法: 施策前2週間 vs 施策後2週間のCVRを比較（同曜日・イベントフラグ除外）

中間確認: 1週間後にCVRのトレンドを確認。悪化の場合は施策を元に戻すことを検討。
```

## 分析結果の信頼性評価

| 信頼度レベル | 条件 | 表現方法 |
|-------------|------|---------|
| 高 | データが十分・代替説明を排除済み・先行例あり | 「データが示すとおり、○○が主因である可能性が高い」 |
| 中 | データはあるが代替説明が残っている | 「○○の可能性が高いが、△△の影響も排除できない」 |
| 低 | データ不足・仮説段階 | 「仮説として○○が考えられるが、確認には△△のデータが必要」 |

## 因果推論の注意事項まとめ

1. **同時変化 ≠ 因果**: A施策とBイベントが同時期の場合、どちらの効果か判別不能
2. **期間が短すぎる**: 1〜2週間のデータで判断するのは危険。施策タイプ別の最低観測期間を守る
3. **複数施策の同時実施**: 複数施策を同時に実施すると各施策の効果が判別できない。可能であれば施策を分けて実施する
4. **サンプルサイズ**: 注文件数が少ない場合（月10件以下）、CVRの変動は統計的に意味がない可能性が高い
5. **回帰バイアス**: 特に悪かった時期の翌期に改善が見られることがある。これは施策効果ではなく統計的回帰の可能性
